## 现状盘点

**主导航（纯图标，无标签/无 tooltip/无 AX 名称）**：①项目栅格（单项目无响应）②对话（三模式）③原始资料 ④搜索 ⑤知识关系图 ⑥Wiki 检查 ⑦待审阅 ⑧深度研究（以⑦页右侧抽屉呈现）+ 底部设置。

**对话页三模式，composer 完全更换**：
- 对话：输入框 + 添加图片 + 网页搜索/AnyTXT checkbox + 路由四档（快速/标准/深入/本地优先）+ 保存 QA。**不显示将用哪个模型**。
- Agent：占位「让 Agent 检查、编辑或操作这个 Wiki…」+「模型: <legacy 值> · 权限: 默认」静态文本；搜索/路由控件全部消失。
- 提取：占位「讨论资料内容或继续追问…」+「写入 Wiki」按钮。

**设置 23 项平铺**，按实际内容归堆：模型配置 ×5 处（LLM 模型 legacy ×15 provider / 模型 Profiles / 向量嵌入 / 图片描述 / 外部信息源的搜索 provider ×6）；工作台 ×5（标签体系/综合/索引/维护/派生状态）；真设置 ×11；其中**模型 Profiles 与派生状态两页在生产被 runtime 开关整页禁用，且提示设 `LLM_WIKI_CORE_WORK_RUNTIME_ENABLED=true` 重启**。

## 三病根

- **R1** 配置/操作/状态混置（设置里 5 个工作台，主导航又有 ⑥⑦ 同类）。
- **R2** 模型配置散落五处 + legacy/runtime 两代同屏 + 新代被 flag 禁用。

## Notion AI 对照（实机，借鉴清单）

- **N1** 单入口零模式（「使用 AI 处理各种任务…」）。
- **N2** 模型选择=composer 右下角小字「自动」，默认自动路由，想指定才点开。
- **N3** 工具/上下文收纳进「＋」与一个滑杆图标，无平铺开关。
- **N4** 能力扩展是可关闭的引导条（connector 图标行），渐进披露而非设置页。
- **N5** 空态建议卡教育能力边界（创建自定义代理/撰写会议议程/分析 PDF 或图片）。
- **N6** 会话按时间分组（上周/过去30天/更早）+ 常驻「新对话 ⌘O」。
- **N7** 文案面向任务不面向机制。
- **N8** 写操作渲染为可审阅变更（accept/reject），过程渲染为步骤+来源引用。

设计总纲：**把选择后置，把过程前置**——发起时零决策，运行中高透明。

## 用户裁定（2026-07-04）

- **D1** 提取双入口并存：资料页「选文件→讨论→写入」+ 对话页拖入/「＋」添加文件，同一条 ingest 流程。
- **D2** 设置 IA 重组 + Wiki 健康中心立独立 SPEC（= SPEC-12）。
- **D3** Work Runtime 生产转正默认开启。
- **D4** 路由四档**删除**（统一 Agent 化后，深度=选哪个 profile 的结果、本地优先=profile 隐私属性，全部收进「自动 ▾」模型选择器语义）。
- **D5** 主导航五分法（对话/资料/探索/Wiki 健康/深度研究）认可。
