# SPEC-16 — UI 交互质量二轮（验收 bug 群收口）

## 1. 问题陈述

SPEC-14 的 A2 走查与 1.0 F 终验都是**抽样级**（导航可达、面板渲染）。2026-07-06 完整操作级 UI 验收（120 次交互、全截图）暴露了抽样盲区下的交互 bug 群：其中两个 P1（审阅队列自相矛盾 #373、代码块横滚推走面板 #374）属于「轻量操作即可撞见、观感像应用坏了」的级别。这些不是 IA 结构问题（SPEC-14 已收口），是**控件级交互正确性**问题。

## 2. 目标

操作级验收清单（见 §5）全项通过：用户在对话/图谱/健康页的日常交互不再出现自相矛盾的数据呈现和布局崩坏。

## 4. 非目标

- 不做 IA 结构调整（SPEC-14 已定型）
- 不动 lint/审阅的判定逻辑本身（判定正确，是快照失效问题）
- Agent 侧行为问题归 SPEC-15

## 5. 验收标准（closeout gate）

真机生产构建操作级走查（复用 2026-07-06 验收清单），全项 PASS：

1. 审阅队列：Agent 创建页面后，同目标页的 pending 建议自动解决/转「查看页面」；Create Page 对已存在页防呆
2. 对话页：超宽代码块上触控板横划只滚 pre 内部；含 130+ 字符不可断 token 的用户消息气泡完整显示
3. 图谱：单击有选中反馈；详情面板离开探索 tab 即不占位；任何状态下鼠标可关闭；打开面板时左侧标题不竖排
4. 健康页：创建缺失页面后 broken-link 条目自动消失（或刷新后消失）；派生状态无「从未重建+已就绪」并存
5. 补测上轮验收盲区：窗口 resize（窄宽度不破版）、多会话切换、模型选择器交互

## 6. 依赖与关联

- 无 runtime 依赖，纯前端轨，可与 SPEC-15 双轨并行
- 验收方法沿用「CUA Driver 后台操作 + 逐项截图」模式，closeout 由子代理执行完整操作级回归
