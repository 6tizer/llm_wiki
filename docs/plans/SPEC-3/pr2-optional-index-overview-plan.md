# SPEC-3 PR2 Plan: Optional Index / Overview In Normal Ingest

> Type: PR execution plan | Status: reviewed / ready for implementation | Owner: Commander | Branch: `codex/spec-3-pr2-optional-index-overview` | Issues: #187, #188

## Goal

Remove `wiki/index.md` and `wiki/overview.md` from normal ingest's required read/generate/write loop.

After PR2, normal ingest must not require, read as mandatory context, ask the model to generate, or wholesale overwrite the root `wiki/index.md` / `wiki/overview.md` pages. Existing files remain user Markdown assets and stay readable/editable/importable.

## Scope

Deliverables:

- Update normal ingest prompts so stage 1 / stage 2 no longer frame root `wiki/index.md` as required current context.
- Update generation prompt requirements so the model no longer has to emit:
  - updated `wiki/index.md`;
  - updated `wiki/overview.md`.
- Update normal ingest write policy so root `wiki/index.md` and root `wiki/overview.md` FILE blocks are skipped with a warning rather than overwritten.
- Preserve nested content pages such as `wiki/projects/index.md` and `wiki/topics/overview.md` with current behavior unchanged; PR2 only removes the root global aggregate pages from normal ingest.
- Keep `wiki/log.md` append behavior unchanged.
- Update focused tests and ingest scenario fixtures so:
  - prompt snapshots do not require index/overview output;
  - parser/path safety still accepts nested index/overview paths where appropriate;
  - root index/overview generated by a model are not written by normal ingest;
  - old root index/overview files are not deleted or overwritten.
- Update `docs/plans/README.md` to mark PR1 merged and PR2 in progress.

## Non-Goals

- No commit operation implementation; PR3 owns commit semantics.
- No runtime DB migration.
- No derived stale marker writes.
- No explicit rebuild/export job for optional index or overview.
- No deletion of existing `wiki/index.md` or `wiki/overview.md`.
- No change to OKF validator/template wording; PR6 owns that wording sweep.
- No broad rewrite of manual chat-based `startIngest` / `executeIngestWrites` unless Architect marks it required for PR2.
- No change to `isSafeIngestPath`; root structural page skipping belongs to normal ingest write policy, while nested `index.md` pages remain valid Markdown assets.

## Implementation Order

1. Run Architect adversarial review on this plan before implementation.
2. Update prompt builders:
   - `buildAnalysisPrompt` should refer to optional existing wiki context without naming a required index file.
   - `buildGenerationPrompt` should request source summary, entity/concept/schema-routed pages, and log entry only; no mandatory root index/overview output.
   - Remove `Current Overview` update context from normal generation; overview becomes optional synthesis/user-authored summary.
   - Sweep the full prompt body for residual `wiki/index.md`, `wiki/overview.md`, `check the index`, and `preserve all existing entries` framing.
3. Update `autoIngestImpl` stable context and prompt calls:
   - stop reading root `wiki/index.md` / `wiki/overview.md` for normal ingest context;
   - avoid counting index/overview in stable context budget;
   - keep existing `index` / `overview` variables as empty strings for call-site compatibility so analysis, generation, review suggestion, and long-source chunk prompt paths self-disable without broad signature churn.
4. Update normal ingest write policy:
   - introduce and test a small root-only helper such as `isRootIngestAggregatePath`;
   - do not reuse `isRootStructuralWikiPagePath` as-is because it also includes `wiki/log.md`, `schema.md`, and `purpose.md`;
   - drop root `wiki/index.md` / `wiki/overview.md` FILE blocks with warnings;
   - keep nested `*/index.md` and `*/overview.md` valid with current behavior unchanged unless schema routing rejects them.
5. Update tests:
   - prompt tests assert generation prompt no longer asks for `wiki/index.md` / `wiki/overview.md`;
   - parse/path tests keep `wiki/index.md` path safety acceptance separate from normal ingest skip policy;
   - scenario test covers model output containing root index/overview and proves existing non-trivial files are byte-unchanged and warnings are surfaced;
   - add a log append regression guard because the root skip branch sits near the log/listing write branches in `writeFileBlocks`;
   - add nested index/overview write coverage distinct from embedding-skip coverage;
   - existing ingest scenarios no longer seed root index unless the scenario explicitly tests compatibility.
6. Run focused tests, Simplicity Gate, Tester Gate, Reviewer Gate.
7. Stage intentionally, run staged GitNexus detect, commit, push, PR, CI/review loop, merge, cleanup.
